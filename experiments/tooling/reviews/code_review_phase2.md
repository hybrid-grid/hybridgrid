## BLOCKER

- **Runner configuration can silently change between blocks.** [campaign.sh:225](</D:/bench-work/campaign.sh:225>) passes only a subset of settings, while the runner inherits `CONFIGURE_FLAGS`, `CPYTHON_VERSION`, `SEED_BASE`, `ALPHA`, `EPSILON`, `WARM_START`, `DRIFT_AT`, durations, `MIN_TASKS`, and `DRY_RUN` from the environment ([bench_exp.sh:17](</D:/bench-work/hybridgrid/scripts/bench_exp.sh:17>)). `next_round` validates none of these ([campaign.sh:127](</D:/bench-work/campaign.sh:127>)); on `ROUND_START>1`, the runner preserves the old `meta.json` while using current environment values. This can mix configurations or change randomized order within one scenario. **Fix:** explicitly pin/pass every runner input, force `DRY_RUN=0` and `MIN_TASKS=`, and validate all immutable `meta.json` fields before resuming.

- **An unclean termination is not counted toward the two-block-rerun cap.** The ledger is updated only after `wait` returns ([campaign.sh:231](</D:/bench-work/campaign.sh:231>), [campaign.sh:236](</D:/bench-work/campaign.sh:236>)). A reboot, campaign kill, or terminal loss leaves partial files but no ledger entry; relaunch archives and reruns them at [campaign.sh:220](</D:/bench-work/campaign.sh:220>) without incrementing the cap. Repeated crashes can therefore exceed hypotheses §3 silently. **Fix:** atomically write an active-attempt record before launching the runner; clear it only after an observed exit/manual stop. On startup, convert an abandoned non-manual attempt into a ledger entry before permitting another run.

- **The documented launch command creates an approval file that the campaign rejects.** The plan writes both `E2_LAMBDA=RUN` and an `approved=... reason=...` line ([ke-hoach-thi-nghiem-2.md:166](</D:/Đồ án tốt nghiệp/hybridgrid/docs/thesis/ke-hoach-thi-nghiem-2.md:166>)), but [campaign.sh:52](</D:/bench-work/campaign.sh:52>) requires exactly one line. **Fix:** write only `E2_LAMBDA=RUN|SKIP` to the file and append the reason solely to `campaign.log`.

## MAJOR

- **The one-time lambda decision is not immutable.** `phase_decision` rereads the editable file at startup and again upon reaching E2-perm ([campaign.sh:190](</D:/bench-work/campaign.sh:190>), [campaign.sh:209](</D:/bench-work/campaign.sh:209>)). Changing `SKIP` to `RUN` after partial E2 results permits E2-lambda as if preregistered. Unchanged `SKIP` resumes correctly, but immutability is unenforced. **Fix:** create an immutable decision/hash record with no-clobber semantics and reject all later differences.

- **Reboot recovery can wait 120 seconds and can signal unrelated PID-reuse victims.** [stop_campaign.sh:20](</D:/bench-work/stop_campaign.sh:20>) signals stored PIDs without validating process identity, and its wait loop tests only whether `campaign.pid` exists ([stop_campaign.sh:23](</D:/bench-work/stop_campaign.sh:23>)). After reboot it waits the full timeout even when the process is gone; reused MSYS PIDs may be killed. **Fix:** store a run token/start time, verify command line and liveness, remove dead stale locks immediately, and never signal an identity mismatch.

- **TERM targets the correct runner Bash PID, but prompt cleanup is not guaranteed.** `$!` at [campaign.sh:228](</D:/bench-work/campaign.sh:228>) is the background runner Bash, so MSYS `kill -TERM` should reach its trap ([bench_exp.sh:240](</D:/bench-work/hybridgrid/scripts/bench_exp.sh:240>)). Bash defers trapped signals while blocked in foreground external commands, however. The 120-second `-9` fallback bypasses the EXIT trap and does not kill background client subshells/docker-exec descendants ([bench_exp.sh:467](</D:/bench-work/hybridgrid/scripts/bench_exp.sh:467>)). Compose-down removes containers and in-container `stress-ng`, but does not prove host descendants exited. **Fix:** launch the runner in a dedicated process group/session, signal the group, bound Docker commands, and verify both the process tree and containers after forced termination.

- **Docker cleanup verification misses stopped/orphan containers.** It uses `docker compose down` without `--remove-orphans` and checks only running containers with `docker ps -q` ([stop_campaign.sh:34](</D:/bench-work/stop_campaign.sh:34>), [stop_campaign.sh:39](</D:/bench-work/stop_campaign.sh:39>)). **Fix:** use `down --remove-orphans` and verify with `docker ps -aq --filter ...`.

- **Missing `results.csv` or `meta.json` is treated as a fresh scenario.** [campaign.sh:124](</D:/bench-work/campaign.sh:124>) returns block 1 whenever either file is absent. The runner then truncates aggregate files ([bench_exp.sh:198](</D:/bench-work/hybridgrid/scripts/bench_exp.sh:198>)), potentially destroying a damaged but substantial dataset while leaving later-round raw files behind. **Fix:** distinguish a genuinely empty/first-warm-up directory from a damaged scenario; stop for inspection if artifacts beyond the safe block-1 prefix exist.

- **Preflight evidence is overwritten on every retry of the same block.** The filename is always `preflight_r$rs.txt` ([campaign.sh:221](</D:/bench-work/campaign.sh:221>)), and preflight’s `tee` truncates it ([preflight.sh:15](</D:/bench-work/preflight.sh:15>)). This loses the environment record for earlier attempts. **Fix:** include an attempt/run identifier or archive the prior preflight report.

- **The stop test gives false confidence.** Its sleep runner is merely `exec sleep 60` ([test_campaign.sh:42](</D:/bench-work/tests/test_campaign.sh:42>)); it cannot exercise runner traps, Docker children, or process-group cleanup. Worse, the “mid-cell archive” assertion reuses partial files created by the preceding request-stop case ([test_campaign.sh:150](</D:/bench-work/tests/test_campaign.sh:150>), [test_campaign.sh:161](</D:/bench-work/tests/test_campaign.sh:161>)). **Fix:** isolate those cases and add the planned real S5 test, block-7 preservation, reboot/abandoned-attempt, inherited-environment, PID-reuse, SKIP immutability, and forced-kill descendant tests.
